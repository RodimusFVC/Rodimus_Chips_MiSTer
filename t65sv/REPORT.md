# t65sv — report

t65sv is one synthesizable SystemVerilog 6502-family core. In Mode "00" it is cycle-for-cycle and pin-for-pin
identical to **T65 Ver 315 SzGy April 2020** (NMOS including the undocumented opcodes), including every place
where T65 differs from silicon. Parameters add the 6510/8500, 6507, 2A03/2A07, 65C02 (WDC / Rockwell /
Synertek-GTE 65SC02) and 65C816 variants; each folds away at default parameters.

Target: Quartus 17.0, Cyclone V 5CSEBA6U23I7, area first. Synthesis numbers below are yosys `synth_intel_alm`
estimates (no Quartus in this environment).

## 2. Design decisions

**Mode "00" is T65, not silicon.** t65sv is a re-expression of T65's own architecture in SystemVerilog: the same
registers, the same micro code (`T65_MCode` as one `always_comb` block producing the same control signals), the same
pipelined write-back (A/X/Y/P are written at MCycle 0 of the next instruction), the same `Break`/`BreakAtNA`,
`BAQuirk`, `rdy_mod`, `BusB_r`, `really_rdy = Rdy | ~WRn_i` and NMI/IRQ latching, and the same reset behaviour
(the registers T65 leaves unreset keep their value while `Res_n` is low: T65's `Res_n_i` is their synchronous
enable). That is why every pin matches on every clock, including T65's deviations from NMOS silicon (JAM opcodes
are 2-cycle NOPs, taken branches are one cycle early on the bus, see 3.4). Nothing was "fixed".

| Decision | Choice and reason |
|---|---|
| 65C02 implementation | A second micro-code block (`c02_mcode`) for the 65C02, selected per instruction by `c02 = (C02 != 0) && (C02_FIXED \|\| Mode_r != 00 && Mode != 00)`. With `C02 = 0`, or `Mode` tied to `00`, `c02` is constant 0 and all 65C02 logic folds away (proven formally, 3.9). 65C02-only controls: `PCDec` (JMP (a,x)), `PCHfix` (branch page fix one cycle after PCL, as on the CMOS parts), `BAInc16` (JMP (a) without the page-wrap bug), `Hold` (WAI/STP), STZ write data, TSB/TRB/BIT #/RMB/SMB ALU ops, the 1-cycle NOP decode. |
| `Mode` encoding (`t65sv_T65`) | `"00"` NMOS (T65-identical); `"01"`, `"10"` and `"11"` all select the 65C02 of flavour `C02` (default 1 = WDC). T65's own `"01"` is a partial 65C02 (it passes 108 of 254 opcodes of SST wdc65c02, see 3.5) and its `"10"` is a partial 65816; neither is reproduced. `C816 = 1` makes the core a 65C816 regardless of `Mode` (a run-time 6502/65816 switch would cost both engines). With `C02 = 0` `Mode` is ignored (NMOS only). |
| `C02_FIXED` | 1 = always 65C02, `Mode` ignored, so a 65C02-only top does not carry the NMOS table (`t65sv_65C02` uses it). |
| Flavours | `C02 = 1` WDC W65C02S (bit ops RMB/SMB/BBR/BBS, WAI, STP), `2` Rockwell R65C02 (bit ops, no WAI/STP), `3` Synertek/GTE 65SC02 (neither). Unused opcodes follow the data sheets and Dormann's 65C02 test: x3/xB are 1-byte 1-cycle NOPs; on parts without bit ops x7/xF are 1-byte 1-cycle NOPs; CB/DB are 1-byte 1-cycle NOPs where WAI/STP do not exist. SST's Rockwell/Synertek sets model CB/DB and x7/xF differently (3.5); where the references conflict I followed the data sheets / Dormann and list the SST cases. |
| 65C02 decimal | N and Z from the decimal result, one extra cycle; SBC uses Bruce Clark's 65C02 sequence. In the extra cycle the core re-reads the operand address (immediate: the operand byte; otherwise the last address). SST uses a per-set constant address there (3.5). |
| `NO_DECIMAL` (2A03/2A07) | D can be set/cleared/pushed but ADC/SBC/ARR stay binary. `BCD_en` (the input C64_MiSTer's T65 has had since 2020) does the same at run time; it is latched at Sync like upstream and is a `tri1` on `t65sv_T65` so existing instantiations that do not connect it keep decimal mode. |
| 6510/8500 (`t65sv_6510`) | DDR at $0000, data at $0001, reset clears both; reads of $00/$01 return the port (data & DDR \| pins & ~DDR); the accesses still appear on the external bus as on the chip; `PORT_BITS` (default 6) pins, the pinless bits keep the last level they drove (on the chip that level is held by capacitance and fades after a long time; the model holds it indefinitely). AEC is passed through as `Bus_En` (the CPU itself is stopped with RDY, as in the C64). |
| 6507 | `A[12:0]`; IRQ/NMI/SO tied inactive (no pins). |
| 65C816 | Separate engine `t65sv816` (section 6), instantiated by a `generate` when `C816 = 1`. With `C816 = 0` it does not exist; with `C816 = 1` the 6502 logic drives nothing and synthesis deletes it. |
| `DEBUG` | T65's `T_t65_dbg` record packed MSB-first in record order: `{I, A, X, Y, S, P}` (48 bits). |
| chip_pool_pkg wrapper | `t65sv_t65(clk, i, o, sync)`: `t65_o_t` has no Sync field, so Sync is a separate output (leave it open where unused); struct outputs assigned field by field (Quartus 17). Mode 00, Abort_n/SO_n inactive. |
| Abort_n | Ignored in NMOS/65C02 modes, exactly like T65 (lint waiver). Used by the 65C816. |
| Decode ROM option | Rejected: a ROM replacing the micro code needs ~8K x 45 bits (≈36 M10K) and M10K reads are synchronous, which would move the decode a cycle and break cycle equality. The micro code synthesises to fewer ALMs than T65's anyway (section 4). |
| Quartus 17 subset | No `for (genvar ...)`, no `'{key: value}` patterns, no part-selects of expressions, no size casts, declare-before-use, struct outputs per field; `tri1` only on the drop-in top. Checked by grep audit and by Verilator `-Wall` lint (3.10). |

## 3. Verification

Everything here is reproducible with `verify/run_all.sh` (download and preparation steps in `verify/README.md`);
the result files quoted are in `verify/results/`. Tools: Verilator 5.020, GHDL 4.1.0, Yosys 0.33, as65 1.42.

### 3.1 Oracle and lockstep

The oracle is T65 itself: the four VHDL files (md5-checked by `verify/ref/gen_ref.sh`) synthesised to Verilog with
GHDL; the only edits are renaming the signal `break` (an SV keyword) and merging GHDL's duplicate `alu_q`
declaration. The lockstep model holds the oracle and t65sv side by side, drives both with the same inputs, and
compares **every T65 output** (`A[23:0]`, `DO`, `R_W_n`, `Sync`, `EF`, `MF`, `XF`, `ML_n`, `VP_n`, `VDA`, `VPA`,
`Regs[63:0]`, `DEBUG[47:0]`, `NMI_ack`) before and after **every** clock edge. The only exception is time 0 before
the first edge: the GHDL netlist sees an asynchronous reset event at simulator start that t65sv does not (both
power up with every register 0 on hardware); comparison starts at the first edge. `Mode` is "00" throughout.

|---|---|---|---|
| `lockstep_random.txt` | 10 seeds x 20M cycles. Random memory (re-stirred), random IRQ levels, NMI pulses, SO pulses, RDY stalls on read and write cycles, Enable gaps, reset pulses mid-instruction, Abort_n toggling, write data fed back or random; stimulus density changes every 64K cycles | 200,000,030 | **0** |
| `sweep.txt` | Directed: for every opcode (256) x operand set (page cross or not) x flags x the cycle offset of the event, 16 event kinds: IRQ, NMI, RDY 1/2/3 cycles, SO, Enable gap, reset, IRQ+NMI, RDY+IRQ, RDY+NMI, short IRQ pulse, IRQ released inside RDY, RDY+SO, Enable+IRQ, none | 115,098,624 in 1,668,096 runs (every opcode >= 6,912 runs) | **0** |

### 3.4 SingleStepTests 6502: T65 vs SST

`build/sst_ls` runs every case of SingleStepTests/65x02 `6502` (256 opcodes x 10,000) in lockstep, comparing the
final state and every recorded bus cycle with SST, and t65sv with T65 on every clock. **t65sv and T65 never
differ (206,719,611 comparisons, 0 mismatches).** Where SST disagrees, it disagrees with T65 itself:

| Opcodes | Cases failing | What T65 (and therefore t65sv) does | What SST records |
|---|---|---|---|
| 02 12 22 32 42 52 62 72 92 B2 D2 F2 (JAM/KIL) | 10,000 each | executes them as 2-cycle NOPs | the CPU jams (SST lists 11 cycles of the halted bus) |
| 10 30 50 70 90 B0 D0 F0 (taken branches) | 39,862 in total (only taken branches; the ~50% not-taken cases pass) | the taken-branch cycle shows `{old PCH, new PCL}` one cycle early; on a page cross the next cycle already shows the final target | cycle 2 reads PC+2 (the next opcode), then the target |

Everything else matches SST exactly, including all undocumented opcodes (SLO, RLA, SRE, RRA, SAX, LAX, DCP, ISC,
ANC, ALR, ARR, XAA/ANE, LXA, AXS/SBX, SHA/AHX, SHX, SHY, TAS/SHS, LAS) and their dummy cycles:
2,400,138 of 2,560,000 cases pass; the failures are exactly the two groups above. The 2A03 build against
SST `nes6502` (decimal disabled) shows the same two groups and nothing else (2,400,274 of 2,560,000 pass; 120,000 JAM + 39,726 taken-branch cases).

| Set | Build | Pass | Failures, all explained |

| wdc65c02 | `C02 = 1, C02_FIXED = 1` | 2,530,025 / 2,540,000 | same |
| rockwell65c02 | `C02 = 2` | 2,530,034 / 2,560,000 | 69/E9 decimal cycle (SST $0059 / $0000); CB, DB: data sheet / Dormann 1-byte 1-cycle NOPs; SST: CB 1-byte 2-cycle, DB 2-byte 4-cycle |
| synertek65c02 | `C02 = 3` | 2,210,021 / 2,560,000 | 69/E9 decimal cycle (SST $0056 / $0000); x7, xF, CB, DB: 1-byte 1-cycle NOPs per data sheet / Dormann; SST: x7 2-byte 3/4-cycle, xF 3-byte 3/4-cycle, CB 1-byte 2-cycle, DB 2-byte 4-cycle |

The SST address in the decimal extra cycle is a constant per set (it differs between three generator runs of the
same behaviour), so it was treated as an artefact of the generator, not as silicon behaviour.

**T65 Mode "01" is not a 65C02.** Running the same wdc65c02 set against T65 with Mode "01" (`sst_wdc_on_T65mode01.txt`)
passes only 108 of 254 opcodes; 1,257,380 of 2,540,000 cases fail (wrong cycle counts, NMOS dummy cycles, missing
65C02 timings and decimal behaviour, JMP (a) page bug, unimplemented bit ops). This is why `Mode` "01"/"10"/"11"
in t65sv selects its own 65C02 rather than reproducing T65's Mode "01".

### 3.6 Lorenz suite (C64)

Programs from VICE testprogs `general/Lorenz-2.15/src` (r46309), the C64 versions (no -dtv/-plus4/disk-change
variants): 308. Each is run in two environments, both with oracle + t65sv in lockstep:

* **flat C64** (`build/c64flat_ls`): real BASIC/KERNAL ROMs, RAM, the $01 port, a CHROUT trap, no VIC/CIA. The test
  signals pass/fail with its first write to $D7FF.
* **mini-C64** (`build/c64_lockstep`): cycle-exact C64 built from the fpga64 32-phase bus sequencer with the
  C64_MiSTer VIC-II (converted with GHDL) and CIA (`mos6526.v`, 6526 or 8521), real ROMs, booted once and restored
  from a Verilator snapshot for each program. Used for the programs that need CIA/VIC timing.

The long C64 runs used harness binaries built before the 65C816 was integrated; that RTL is formally equivalent to
the final `t65sv` with `C816 = 0` (3.9), and the harnesses rebuilt from the final `rtl/` reproduce sampled programs
with identical results and cycle counts (`results/final_rtl_c64_smoke.txt`).

**300 of 308 programs pass; t65sv and T65 never differed** (every flat and mini-C64 run in
lockstep: 354 runs, 4,042,322,266 cycles, 0 mismatches).
257 pass in the flat C64; of the 51 that need real C64 hardware (CIA timers and interrupts, the VIC-II raster,
the I/O port) or did not finish in the flat shim's 1-hour limit, 43 pass on the mini-C64.

The 8 that fail are the CIA timer read-out tests cia1ta, cia1tb, cia2ta, cia2tb, each with the old and
the new CIA. They run for 25-40M cycles and then report a timer / ICR value read two cycles away from what a real
C64 gives (e.g. test #08: `after 0e 00 00`, expected `10 81 00`). These are the mini-C64's CIA model and clocking
(C64_MiSTer `mos6526.v` behind my fpga64-style sequencer), not the CPU: T65 in the same lockstep run reads exactly
the same values on every cycle, and every other CIA test (cia1tab, cia1tb123, cia1pb6/7, cia2pb6/7, cia2tb123,
icr01, imr, irq, nmi, oneshot, cntdef, cnto2, loadth, flipos, all with old and new CIA where they exist) passes.

## 5. Upstream survey (MiSTer-devel T65 copies)

Full report: `survey/SURVEY.md` (one row per repository with md5s, dates and EOL style) and `survey/diffs/` (a raw
unified diff, reference → variant, for each distinct variant). Method: the GitHub code-search API is blocked in this
environment, so the repository list came from the MiSTer wiki `Cores.md` (361 MiSTer-devel repos) plus ~70 guessed
names; each was cloned treeless and scanned for T65 files. Repos not linked from the wiki may be missed.

* **57 repositories** carry a T65 copy, in **17 distinct variants** (after normalising CRLF and trailing blanks).
* The Galaxian reference (Ver 315) is byte-identical to `C64_MiSTer` / `C128_MiSTer` `rtl/t65` at **351ced1
  (2020-04-30)**, the first Ver 315 import, before any MiSTer changes. BBCMicro, Arcade-Centipede,
  Arcade-DECOCassette and Arcade-SNK6502 carry the same bytes.
* **Newest maintained upstream: `MiSTer-devel/C64_MiSTer` `rtl/t65`** (T65 files last changed 66acee6,
  2026-06-08; C128 identical, CBM-II re-synced 2026-09-05). Its changes against Ver 315 (still labelled "Ver 315"):
  1. `BCD_en` input (from NES_MiSTer 0ba9a3a, 2018), latched at MCycle 0, gating every decimal correction;
  2. default values on Rdy/Abort_n/IRQ_n/NMI_n/SO_n;
  3. gyurco's 2022-11 interrupt rework (`IRQReq`/`NMIReq`, IRQ/NMI cycle chosen at the opcode fetch, branch delay
     keyed on `Jump = "11"`);
  4. S decremented during reset in Mode "00" (the 3 dummy pushes);
  5. `NMI_ack` as a one-cycle pulse at MCycle "001" (2026-06, from C64MEGA65).
* NES_MiSTer is a divergent fork (savestates, `Pwr_n`, KIL halt, `BCD_en` also in the micro code) and not a good
  general upstream. Several arcade cores still use Ver 313 or the Ver 301 opencores code.
* `BCD_en` exists upstream (groups B–I, K/K2 of the survey). t65sv adopts the port name and semantics (decimal
  disabled when 0, latched at Sync) so that `t65sv_T65` drops into C64_MiSTer-style instantiations, while Mode "00"
  stays Ver 315: items 3–5 are behavioural changes relative to the oracle and are **not** in t65sv.

**Status: complete.** `t65sv816` passes every SingleStepTests 65816 case, both sets, on final state and on every bus
cycle including VDA, VPA, VPB, RWB, E, M, X and MLB: **5,080,400 / 5,080,400** (emulation 2,540,200, native
2,540,200; 0 mismatches). The same run through the integrated path `t65sv_T65 #(.C816(1))` gives the same result
(5,080,400 / 5,080,400 pass).

### 6.1 How it is built

Built from the WDC W65C816S data sheet (T65's Mode "10" was not used). Emulation and native modes, M/X widths
(8/16-bit A and index registers, XH/YH cleared when X=1), DBR/PBR/D/16-bit S, 24-bit addressing, all 24 addressing
modes, MVN/MVP (one 7-cycle iteration per byte, re-fetching the opcode), BRK/COP/WDM, WAI/STP, IRQ/NMI/ABORT/RESET.

* **Sequencer.** Each instruction is a short list of micro-ops, one per bus cycle (`uprog(opcode, step)`, about 35
  kinds: operand fetch, internal, index-carry internal, data read/write low/high, RMW read/modify/write, pointer
  read, push/pull of each source, vector, block move, wait, stop). A micro-op may carry a **skip condition**:
  8-bit width, DL = 0, no index carry (reads with 8-bit X only), branch not taken, no emulation-mode branch page
  cross, emulation mode. A skipped micro-op takes no time; a not-taken branch ends the instruction. Two lookups
  (`step` and `step + 1`) are enough because a skipped micro-op is never followed by another skippable one.
* **Datapath.** One shared 24-bit effective-address adder (direct page + operand, the index step of d,x / d,y /
  (d,x), stack relative, absolute/long/pointer + index), one PC adder (increment, branch, BRL, PER, PC-1 for
  JSR/JSL, PC-3 for the MVN/MVP repeat, RTS/RTL +1), one stack adder, one incrementer per index register, one
  read-modify-write unit (memory and accumulator), one read-type ALU with the 65816 decimal algorithm (nibble
  correction, V before the last correction).
* **Pins.** `A[23:0]` carries the bank in `A[23:16]` (on the chip it is multiplexed onto D7..D0 during PHI2 low);
  `VDA`, `VPA`, `VP_n` (VPB), `ML_n` (MLB), `E`, and M/X as two outputs `MF`/`XF` (the chip multiplexes them on MX).
  E/M/X show the values at the start of the instruction until its last cycle (an RTI or PLP changes them only
  for the next opcode fetch, as SST records).
* **Bus conventions measured from SST** and implemented: an internal cycle repeats the previous address, except
  the first internal cycle of implied/stack instructions (PBR:PC) and the index-carry cycle of a,x / a,y / (d),y
  (DBR:high:(low+index) without the carry); emulation-mode RMW rewrites the old value with VDA = VPA = 0; in
  emulation the "65816-only" stack instructions (PEA, PEI, PER, PHD, PLD, PLB, JSL, RTL, JSR (a,x)) address the stack
  with the full 16-bit S and leave SH = 01 afterwards, while the 6502 ones wrap in page 1; direct page indexed
  addressing wraps within the page in emulation with DL = 0.
* **ABORT.** The architectural state at each opcode fetch is kept; when Abort_n was low during an instruction,
  its bus cycles still complete (as on the chip) but at the next boundary all registers return to the snapshot and
  the ABORT sequence pushes the aborted opcode's address (vector 00FFE8 / 00FFF8).
* **Reset.** `Res_n` low: E = 1, M = X = I = 1, D flag 0, D = 0000, DBR = PBR = 00, S = 01FF, X = Y = 0. After release:
  one discarded fetch, one internal cycle, three stack reads (S decremented by 3, as the NMOS/CMOS 6502 do; the
  W65C816S data sheet does not specify the bus here), vector 00FFFC with VPB.
* **Integration.** `t65sv #(.C816(1))` instantiates `t65sv816` in a `generate` branch and drives every T65 port from
  it (`Regs`/`DEBUG` keep T65's layouts with the low bytes); the 6502 logic then has no load and synthesis removes
  it. `C816 = 0` (default): the branch does not exist. `t65sv_65C816` is a top with the 65816 pin names plus
  `Wait_n` (low while WAI waits; the chip drives RDY low then). Mode, SO_n and BCD_en are ignored with C816 = 1.

SST conventions (also documented in `tb/sst816.cpp`):
* emulation-mode cases give S with an arbitrary high byte; the harness loads S as 01:SL (the 65816 forces SH = 01
  in emulation, and every expected cycle and final S agree with that);
* WAI and STP cases end with a cycle `[0, null, "---w----"]` (no VDA/VPA/VPB, no E/M/X): the generator's halt
  marker, not a bus cycle; it is not compared (t65sv816 is waiting/stopped there, `Wait_n` low for WAI).

What SST cannot reach and is therefore only covered by the directed tests above (data-sheet behaviour, not
cycle-checked against a reference): interrupt/ABORT/RESET timing, the interrupt sampling point, WAI wake-up
latency, RDY. ABORT restores the registers but cannot undo memory writes the aborted instruction already made;
that is also what the chip does.

## 7. Not done / limitations

* **No Quartus run.** Quartus 17.0 is not available here. Area and depth are yosys `synth_intel_alm` estimates;
  Quartus 17 compatibility rests on keeping to the listed language subset (grep audit plus Verilator lint), not on
  a Quartus compile. A Quartus 17 compile of `t65sv_all.sv` (top `t65sv_T65`) is the first thing to run on your side.
* **Lorenz / VICE programs that still fail** are never CPU disagreements: every run had t65sv and T65 in lockstep
  with 0 mismatches, so T65 fails them identically. The 8 Lorenz CIA timer read-out tests fail on the mini-C64's
  CIA model / clocking; the 3 VICE ANE tests and the 16 JAM tests check silicon behaviour that T65 does not have
  (RDY side effects on ANE's unstable bits, the CPU halting on JAM). Details in 3.6 / 3.7.
* **T65 vs silicon** is reported, not changed (3.4): JAM opcodes run as NOPs and taken branches show the target a
  cycle early, exactly like T65. That is the specification for Mode "00".
* **65C02 reference conflicts** (3.5): unused opcodes and the decimal extra-cycle address follow the data sheets
  and Dormann where SST differs.
* **65C816 interrupts, ABORT, RESET, WAI/STP wake-up and RDY** are checked only by directed tests (section 6.2);
  SingleStepTests 65816 does not cover them.
* **C64 ROM images, the VIC-II/CIA RTL, the Dormann sources and the T65 VHDL are not redistributed** in this
  package; `verify/README.md` fetches them from their own repositories.
